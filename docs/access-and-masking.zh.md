# 访问与掩码

每个请求都会检查访问权限。
对某个主体不可见的来源，从不对该主体读取、引用或摘要。
受限标识符在每个 JSON 答复中、在响应边界处被掩码。

## 账户

工作区自带五个演示账户。
它们保存在私有 PostgreSQL 中。

| 账户 | 角色 | 数据集 |
| --- | --- | --- |
| `admin` | admin | Financial Services（金融服务）、Manufacturing（制造） |
| `finance_reader` | reader | Financial Services（金融服务） |
| `finance_restricted` | restricted | Financial Services（金融服务） |
| `manufacturing_reader` | reader | Manufacturing（制造） |
| `manufacturing_restricted` | restricted | Manufacturing（制造） |

角色授予能力。

| 角色 | 能力 |
| --- | --- |
| admin | 查询、查看洞察、上传、处理、审核、发布、构建图、构建目录 |
| reader | 查询、查看洞察 |
| restricted | 查询、查看洞察；部分来源不可见 |

### 不可见来源

每个受限账户都有不可见的来源。

- 金融服务的受限读者：一份负面媒体报告和通话录音。
- 制造的受限读者：两份合同。

### 会话

会话是 cookie 中的一个随机令牌。
服务器只存储它的 SHA-256 哈希。
一个会话持续 8 小时。
首次访问会打开一个管理员会话。切换账户会替换该会话。

!!! note "演示账户"
    这些账户仅用于演示。
    它们没有密码。
    只在本身受访问控制的部署上使用它们，例如 Cloudera AI 应用。

## 在哪里强制执行访问

| 位置 | 规则 |
| --- | --- |
| 每个 `/api/*` 路由 | 主体必须被授予该数据集 |
| 分块和链接 | 来自不可见来源的分块不可见 |
| 概念 | 只要有任何不可见的证据段落，该概念对此读者就隐藏示例并清空同义词 |
| 仅文档概念 | 含义被替换为不可见提示 |
| 回答 | 有任何不可见段落的概念被排除；只有不可见来源才能回答的问题，以“source withheld”拒答 |
| 发布版本 | 包含账户无法读取的来源内容的发布版本被隐藏 |
| 事实明细 | 不可见来源被编译器自身的检查拒绝 |
| 进度记录 | 不指明答复本身所说之外的任何来源 |
| 实体 360 | 每条链接、段落和概念都要通过可见性检查 |

### 为什么概念需要小心

概念的标签、含义和同义词，由模型根据它所有的证据写成。
一个不可见的段落可能通过它们泄露。
论文报告了这样一个故障，发现得较晚。
目录路由返回了概念的示例，即从证据分块中复制的短语。
其中一个来自不可见的来源。
修复是：只要有任何证据段落不可见，就隐藏示例、清空同义词，并替换仅文档概念的含义。
锚定在模型上的含义保留，因为它来自模型。

## 标识符掩码

数据模型对某些列规定：从不显示其值。
服务器在每个 JSON 答复中掩码这些值。

| 类型 | 按名称匹配的列 |
| --- | --- |
| 账户 | `AccountNumber`, `AccountNo`, `AccNum`, `CounterpartyAccountNo` |
| 客户 | `CustomerID` |
| 客户经理 | `RMID` |

### 掩码什么

要掩码的值集合有两部分。

- 受限列所持有的值。它们只读取一次。
- 证据链接为某个受限列陈述的值，例如通话中说出而没有任何表持有的标识符。
  它们每 20 秒重新读取一次。
  陈述的值需要有一个字母或八位数字，因为较短的纯数字可能是被误读的金额。

四个字符及以下的值不会被收集。

### 如何掩码

答复中的每个字符串都会扫描包含数字的完整标记。
等于某个受限值的标记会被替换。
属于小数或分组数字一部分的纯数字标记保持不变。
名称是受限列的整数字段也会被掩码。

掩码后的形式保留尾部：

```text
•••• 1234     (values of eight characters or more keep four)
•••• 34       (shorter values keep two)
```

标记匹配只使用 ASCII 字符类。
紧挨着中文文本、中间没有空格的标识符，仍然是一个标记。

### 例外

- 来源身份（`id`、`sourceId`、哈希）保持不变。
- 实体 360 路由保留客户和客户经理的标识符，因为它按这些标识符搜索。账户号码在那里仍然被掩码。

### 身份号码

提取文本中的国民身份号码，在文本到达浏览器之前被掩码。
其模式来自 `multimedia_rag/fields.py` 中继承的字段提取器。
存储的表单单元格保存掩码后的值。

## 实体从不合并

实体保留它们为人所知的键。
文档中的名称从不解析为客户标识符。
通话转写中陈述的客户标识符，可能与表中的标识符相差一个字符。
两者被显示为相似，但从不合并。

## 请求来源

服务器只接受同源请求。

- `Host` 头必须是带服务器端口的回环地址，或 `V2_ALLOWED_HOSTS` 中列出的主机。
- 跨站或同站的 fetch 请求被拒绝。
- 带有 `Origin` 头的请求必须来自同一主机。
- 更改状态的请求必须带有 `Origin` 头。

在 Cloudera AI 应用代理之后，把 `V2_ALLOWED_HOSTS` 设置为应用的公共主机名。
见[部署](deployment.md)。
